## 四、BCI算法详解（答辩必问，重点准备）

### 规范依据
《JTG 5120-2021》第5.2节：

> 全桥 BCI = BCI₁×ω₁ + BCI₂×ω₂ + BCI₃×ω₃ + BCI₄×ω₄

### 权重分配
| 部分 | 权重 | 说明 |
|------|------|------|
| 桥面系 BCI₁ | 0.15 | 桥面铺装、伸缩缝、排水等 |
| 上部结构 BCI₂ | 0.35 | 主梁、支座、横向联系等 |
| 下部结构 BCI₃ | 0.35 | 桥墩、桥台、基础等 |
| 附属设施 BCI₄ | 0.15 | 照明、标志、隔音屏等 |

### 技术状况等级
| 等级 | BCI范围 | 状态描述 |
|------|---------|---------|
| 1类 | ≥90 | 完好/良好 |
| 2类 | ≥80 | 较好 |
| 3类 | ≥60 | 较差 |
| 4类 | ≥40 | 差 |
| 5类 | <40 | 危险 |

### 代码实现
```java
// util/BCICalculator.java
public static double calculateBCI(double deck, double super, double sub, double accessory) {
    return deck * 0.15 + super * 0.35 + sub * 0.35 + accessory * 0.15;
}
```

### 不同桥型的部件权重
- **梁式桥**：主梁 40%、支座 20%、横向联系 15%...
- **拱桥**：主拱圈 45%、拱上建筑 20%...
- **斜拉桥**：主梁 30%、索塔 25%、拉索 25%...
- **悬索桥**：主梁 25%、主缆 25%、吊索 15%...

## 五、安全措施（1分钟）

1. **密码加密**：SHA-256 + 随机盐值，数据库不存明文
2. **SQL注入防护**：全部使用 PreparedStatement
3. **输入校验**：日期格式、经纬度范围、评分范围
4. **角色权限**：管理员/检查员区分，UI级别控制
5. **事务控制**：关键操作使用数据库事务
6. **日志记录**：操作日志持久化到文件

## 九、预判问题与回答

### Q1: "为什么选择C/S而不是B/S？"
> A: 本系统面向道路管理所内部使用，用户数量少（<20人）、数据安全性要求高（桥梁数据敏感）、需要离线操作能力（野外检查无网络），C/S架构在桌面端响应更快、交互更流畅。

### Q2: "BCI是怎么计算的？符合规范吗？"
> A: 严格按照《JTG 5120-2021》第5.2节，采用分层加权：桥面系15%+上部结构35%+下部结构35%+附属设施15%。不是简单平均。系统中实现了不同桥型的部件权重差异，如斜拉桥增加了拉索评分项。

### Q3: "系统中用了GIS吗？怎么实现的？"
> A: 使用了GIS技术。桥梁卡片中记录经纬度坐标，通过OpenStreetMap静态地图API在Swing界面中嵌入地图预览，支持在浏览器中打开查看详细地图。符合任务书"使用GIS技术录入"的要求。

### Q4: "数据库设计有哪些表？关系是什么？"
> A: 5张表。核心是桥梁表，与初始检查、定期检查是1:N关系。定期检查与部件评分是1:N关系。所有外键都设置了ON DELETE CASCADE级联删除。

### Q5: "团队怎么分工的？用了版本控制吗？"
> A: 4人分工：张子健-桥梁管理、郑晟-初始检查、谭容昊-定期检查、曹城钧-用户管理。使用Git进行版本控制，有完整的提交历史，共4次主要提交。

### Q6: "系统有什么安全措施？"
> A: 6层安全：①密码SHA-256+盐值加密 ②PreparedStatement防SQL注入 ③输入格式校验 ④角色权限控制 ⑤数据库事务保证一致性 ⑥操作日志审计。

### Q7: "如果桥梁数量增加到10000座，系统能支撑吗？"
> A: 当前已实现：①数据库索引优化（bridge_no、bridge_name等字段有索引）②连接池减少连接开销 ③日志异步写入。未来可扩展：分页查询、数据库分区、读写分离。
