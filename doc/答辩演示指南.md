## 三、老师常见问题及回答

### Q1：为什么选择 C/S 而不是 B/S？
> "本系统是面向道路管理所内部使用的业务系统，用户固定、数据敏感、操作频繁。C/S 架构可以提供更丰富的桌面交互体验（如表格编辑、本地缓存），且数据不暴露在互联网上，安全性更高。B/S 更适合面向公众的互联网应用。"

### Q2：BCI 的计算依据是什么？
> "依据《JTG 5120-2021》公路桥涵养护规范，BCI = (桥面系评分 + 上部结构评分 + 下部结构评分 + 附属设施评分) / 4。90分以上为1类，80-89为2类，60-79为3类，40-59为4类，40以下为5类。"

### Q3：如果桥梁数据量很大（比如1000座），系统会不会卡？
> "目前系统使用 JDBC 直连数据库，如果数据量很大，可以在 DAO 层增加分页查询（LIMIT/OFFSET），同时在界面加入分页导航组件。我们在设计时预留了分页接口。"

### Q4：系统中有没有考虑数据备份？
> "目前可以通过 SQL Server 的备份功能定期备份数据库。后续可以增加系统的数据导出功能，将桥梁数据导出为 Excel 或 PDF 格式进行离线备份。"

### Q5：你们的分工是怎么做的？
> "张子健负责系统架构和桥梁管理模块；郑晟负责初始检查模块；谭容昊负责定期检查模块和 BCI 算法；曹城钧负责用户权限和统计模块。数据库设计是大家一起讨论确定的，使用 Git 进行版本控制。"

## 四、演示禁忌 ❌

| 不要做的事 | 原因 |
|-----------|------|
| 不要从0开始新建数据库 | 现场建表可能报错，提前建好 |
| 不要演示太长的数据输入 | 容易输错，提前准备好示例数据 |
| 不要一直看代码 | 老师看不懂代码，看界面 |
| 不要4个人都说话 | 主讲1人，其他人补充 |
| 不要演示删除自带的4条数据 | 删了后面演示就没数据了 |

---

## 五、应急备案

如果现场 SQL Server 连不上：
1. 打开 `src/util/DBUtil.java`
2. 把内容换成 `DBUtilSQLite.java` 的代码
3. 把 `lib/sqlite-jdbc-3.44.1.0.jar` 加到依赖
4. 重新运行（SQLite 零配置，一定能跑）
